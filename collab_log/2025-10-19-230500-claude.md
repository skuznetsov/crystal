**Impact**: Trim marker detection fails because current_token is `"?"`, not `"-"`.

## 🐛 Lexer Issue: Identifiers with `?` suffix

### Problem

Crystal allows method names ending with `?` (e.g., `empty?`, `valid?`), but our lexer doesn't recognize `?` as part of identifier.

**Current lexer logic** (lexer.cr:134-140):
```crystal
private def identifier_start?(byte : UInt8) : Bool
  ascii_letter?(byte) || byte == UNDERSCORE
end

private def identifier_char?(byte : UInt8) : Bool
  ascii_letter?(byte) || ascii_number?(byte) || byte == UNDERSCORE
end
```

**Missing**: No support for `?` or `!` suffixes

---

## 🔧 Proposed Fix (for GPT-5 or future)

**Option A**: Extend lexer's `identifier_char?`:
```crystal
private def identifier_char?(byte : UInt8) : Bool
  ascii_letter?(byte) || ascii_number?(byte) || byte == UNDERSCORE || byte == '?'.ord || byte == '!'.ord
end
```

**Option B**: Post-process identifier tokens to check if next byte is `?` or `!` and merge.

**Option C**: Leave as-is and document that macro expressions should avoid `?`/`!` suffixes (workaround).
