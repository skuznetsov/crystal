# Go-to Definition Improvements

## Changes
- Extended `PRELUDE_PATH` resolution so the LSP server prefers `../src/prelude.cr` when run from inside `crystal_v2/`, avoiding unnecessary stub fallback when building locally (`crystal_v2/src/compiler/lsp/server.cr`).
- Enhanced `find_expr_in_tree` to descend into `DefNode`, `ClassNode`/`ModuleNode`/`StructNode`/`UnionNode`, and `BlockNode`, ensuring the smallest AST node under the cursor is selected (crucial for grabbing the identifier inside a call).
- Added `definition_from_call` fallback logic so `textDocument/definition` can resolve implicit `self` calls via `identifier_symbols`, while reusing the member-access handlers for `foo.bar`/`foo&.bar`.
- Added extra `LSP_DEBUG` logging around definition resolution to aid troubleshooting (node kind, callee kind, symbol lookup).

## Verification
- `cd crystal_v2 && CRYSTAL_CACHE_DIR=../.crystal-cache ./build_lsp_debug.sh`
- Exercised the server via JSON-RPC (initialize → didOpen → definition) to confirm:
  * Simple identifier `foo` resolves to its definition span.
  * Method call `bar` inside `Foo#baz` now returns the `def bar` span instead of `null`.
- `cd crystal_v2 && CRYSTAL_CACHE_DIR=../.crystal-cache crystal spec spec/lsp/lsp_rename_spec.cr`

- Logs still mention stub prelude because the real `src/prelude.cr` lacks some stdlib helpers in this environment; the new fallbacks rely on existing name-resolution data and continue to work even under the stub.
