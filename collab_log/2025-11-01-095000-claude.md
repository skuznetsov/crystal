## P1: case/when Bare Case Support

### Problem Discovered
Phase 11 implemented `case VALUE\n when...` but NOT `case\n when...` (bare case).

**Lexer.cr uses bare case**:
```crystal
token = case        # ← No value!
when byte == NEWLINE
  lex_newline
when byte == SPACE
  lex_space
else
  lex_other
end
```

### Root Cause Analysis [LM-DAEDALUS-1, LM-DAEDALUS-2]

**Initial hypothesis**: Parser doesn't support bare case.
**Reality**: Parser tried to parse value ALWAYS.

**Code path**:
```crystal
# Old code (Phase 11)
private def parse_case
  advance                    # Skip 'case' token
  skip_trivia               # Skip whitespace/comments
  value = parse_expression(0)  # ← ALWAYS parses value
  # ERROR: If next token is Newline, parse_expression fails
end
```

**Fix discovery process**:
1. **Attempt 1**: Made value optional based on `current_token.kind == When`
   - Used `skip_whitespace_and_optional_newlines`
   - **FAILED**: Not inside delimiters, so newlines weren't skipped

2. **Attempt 2**: Realized case/when is control structure (like if/while)
   - Should use `consume_newlines` (skip ALL newlines)
   - NOT delimiter-dependent

3. **Success**: Use `consume_newlines` after keywords, `skip_trivia` in bodies

### Implementation

**Key insight**: case/when has **structural newlines** (always skip) vs **delimiter newlines** (skip only inside delimiters).

**Updated parse_case** (parser.cr:1015-1127):

```crystal
private def parse_case : ExprId
  case_token = current_token
  advance
  consume_newlines  # Skip ALL newlines after 'case'

  # Parse optional case value (bare case has no value)
  value : ExprId? = nil
  if current_token.kind != Token::Kind::When
    # Has value: case EXPR
    val = parse_expression(0)
    return PREFIX_ERROR if val.invalid?
    value = val
    consume_newlines
  end

  # Parse when branches
  when_branches = [] of WhenBranch
  loop do
    skip_trivia
    break unless current_token.kind == Token::Kind::When

    advance
    skip_trivia

    # Parse when conditions (comma-separated)
    conditions = [] of ExprId
    loop do
      conditions << parse_expression(0)
      skip_trivia
      break unless current_token.kind == Token::Kind::Comma
      advance
      skip_trivia
    end

    # Optional "then" keyword
    if current_token.kind == Token::Kind::Then
      advance
    end

    consume_newlines

    # Parse when body
    when_body = [] of ExprId
    loop do
      skip_trivia
      break if current_token.kind.in?(When, Else, End, EOF)
      when_body << parse_statement
      consume_newlines
    end

    when_branches << WhenBranch.new(conditions, when_body, span)
  end

  # Parse optional else
  if current_token.kind == Token::Kind::Else
    advance
    consume_newlines
    else_body = [] of ExprId
    # ... parse else body ...
  end

  # Expect 'end'
  unless current_token.kind == Token::Kind::End
    emit_unexpected(current_token)
    return PREFIX_ERROR
  end
  advance

  @arena.add_typed(CaseNode.new(span, value, when_branches, else_body))
end
```

**Pattern for control structures**:
- After keywords (`case`, `when`, `then`, `else`): `consume_newlines`
- Before keywords in loop checks: `skip_trivia`
- Inside statement bodies: `skip_trivia` + `consume_newlines` after each statement

## Lessons Learned

### 1. **Context Matters for Newlines**
Not all newlines are equal:
- **Delimiter context**: Inside `()`, `[]`, `{}` → skip newlines
- **Control structure context**: After `case`, `when`, `if` → skip newlines
- **Top-level context**: Between statements → newlines are separators

### 2. **Test with Real Code**
Synthetic tests passed, but real code (lexer.cr) revealed bare case issue.
Always test parser on its own source code!

### 3. **Incremental Debugging**
[LM-MAIEUTIC] and [LM-DAEDALUS] patterns helped:
- Questioned assumptions about delimiter-based approach
- Analyzed failure modes systematically
- Found root cause (bare case not supported)

### 4. **Pattern Recognition**
case/when follows same pattern as if/unless and while/until:
- Structural newlines after keywords
- Statement-level newlines in bodies
- This pattern applies to ALL control structures
