# `.is_a?` Type Path Parsing

## Changes
- Updated `parse_is_a` in the frontend parser to reuse `parse_type_annotation`, allowing full type paths (e.g., `Frontend::DefNode`) and complex annotations inside `.is_a?(...)` without syntax errors (`crystal_v2/src/compiler/frontend/parser.cr`).
- Added block/proc scope handling to `Semantic::NameResolver`, so block parameters and nested identifiers resolve correctly (supporting Cmd+Click/F12 inside iterator blocks) (`crystal_v2/src/compiler/semantic/resolvers/name_resolver.cr`).
- Tweaked `debug_tests/check_lexer.cr` to use proper require paths and display readable parameter names.
