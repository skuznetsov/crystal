## Root Cause Analysis (Landmark Protocol)

### [LM-DAEDALUS-1] CROSS-BRANCH COMPARISON

**Observation**: Simple types work, namespaced types without value work, but combination fails.

**Hypothesis Tree**:
```
Why does `x : Token::Kind = foo` fail?
│

│   → Tested: parse_prefix condition checks

│
├─ [B] parse_type_annotation incomplete
│   → Tested: Token enum analysis
│   → Result: ✅ ROOT CAUSE FOUND!
│
└─ [C] parse_statement mishandles TypeDeclarationNode
    → Not tested (B was root cause)
```

### [LM-CASSANDRA-1] TOKEN ANALYSIS

**Checked Token::Kind enum** (token.cr:154):
```crystal
ColonColon  # :: (Phase 63: path expression)
Colon       # : (line 165)
```

**Key Discovery**: `::` is Token::Kind::ColonColon, NOT Token::Kind::Operator!

**parse_type_annotation case statement** (parser.cr:528):
```crystal
when Token::Kind::Operator
  # Include type-related operators: ::, |, ?, *, ->, (, ), [, ]
  type_tokens << token_text(token)
```

**Problem**: Comment says `::` is handled, but check is ONLY for `Operator`, not `ColonColon`!

### [LM-MAIEUTIC-1] TRACE THROUGH

**For input** `Token::Kind = foo` (after `:` consumed):

1. token = `Token` (Identifier) → ✅ matches, advance
2. token = `::` (ColonColon) → ❌ NO MATCH in case statement!
3. Line 539: `else` branch → `break`
4. Returns `"Token"` only (missing `::Kind`)
5. current_token still at `::` (never advanced)
6. parse_type_declaration_from_identifier line 565: `if current_token.kind == Token::Kind::Eq`
7. Check FAILS (current_token is `::`, not `=`)
8. Returns TypeDeclarationNode with type="Token", no value
9. parse_statement sees current_token is eventually `=`
10. Tries to make assignment with TypeDeclarationNode as target → ERROR!

**Verification**:
- `x : Token::Kind` works because no `=` to trigger assignment
- `x : Int32 = 42` works because no `::` to break parse_type_annotation

## The Fix

**File**: parser.cr (line 528)

**Change**: Add `Token::Kind::ColonColon` to case statement

```crystal
# BEFORE (parser.cr:522-533):
when Token::Kind::Operator
  # Include type-related operators: ::, |, ?, *, ->, (, ), [, ]
  type_tokens << token_text(token)

# AFTER (parser.cr:528-533):
when Token::Kind::ColonColon
  # Namespaced types: Token::Kind
  type_tokens << token_text(token)
when Token::Kind::Operator
  # Include type-related operators: |, ?, *, (, ), [, ]
  type_tokens << token_text(token)
```

**Why This Works**:
- ColonColon now matches case branch
- parse_type_annotation collects full `Token :: Kind`
- Advances past `::` token
- current_token is now `Kind` (identifier)
- Continues parsing, advances
- current_token is now `=`
- Line 565 check succeeds
- Value is parsed correctly
- Returns complete TypeDeclarationNode

## Knowledge Gained

### Pattern: Token Kind Mismatch in Parser

**Symptom**: Case statement comment lists tokens but doesn't actually handle them

**Root Cause**: Token has dedicated enum value (ColonColon), not generic Operator

**Detection**:
1. Check Token::Kind enum for specific token
2. Verify case statement includes that specific kind
3. Don't rely on comments - they can be wrong!

**Fix**: Add specific Token::Kind case, not just generic Operator

**Applicability**: Any parser using token kind enums

**Tags**: `parser`, `token-handling`, `case-statement`, `Crystal`, `type-annotation`

**Method Used**: DAEDALUS (cross-branch) + CASSANDRA (token analysis) + MAIEUTIC (trace)
