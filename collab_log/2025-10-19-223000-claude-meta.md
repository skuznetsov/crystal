**Meta-lesson**: **State lifecycle analysis** - track WHERE variables are set/read/reset across control flow.

### Question 2: What made the final solution work?

**The critical realization**:
```crystal
# BEFORE (broken):
if trim_next_left
  skip_macro_whitespace_after_escape
  trim_next_left = false  # ← RESET HERE
end
# ... many lines later ...
flush_macro_text(buffer, pieces, trim_next_left)  # ← Using false!

# AFTER (fixed):
if trim_next_left
  skip_macro_whitespace_after_escape
  trim_final = true       # ← PRESERVE STATE
  trim_next_left = false
end
# ... many lines later ...
flush_macro_text(buffer, pieces, trim_final)  # ← Using true!
```

**Pattern recognized**: **Dual-purpose variable problem**
- `trim_next_left` used for TWO purposes:
  1. Control flow (should we skip whitespace NOW?)
  2. Final state (should we trim at END?)

**Solution**: Separate concerns → `trim_next_left` (control flow) + `trim_final` (final state)

## 🎯 Pattern Crystallization

### New Pattern Learned: "Dual-Purpose Variable Anti-Pattern"

**Definition**: When single variable serves both immediate control flow AND later state preservation.

**Symptom**: Variable reset in middle of logic, breaking later usage.

**Solution**: Split into two variables:
- One for immediate control (can be reset)
- One for final state (preserved until use)

**Generalization**:
```crystal
# Anti-pattern:
flag = compute_condition()
if flag
  do_action()
  flag = false  # Reset for control flow
end
# ... later ...
final_action(flag)  # Broken! Using false instead of original value

# Pattern:
flag = compute_condition()
preserve_flag = false
if flag
  do_action()
  preserve_flag = true  # Preserve for later
  flag = false
end
# ... later ...
final_action(preserve_flag)  # Works! Using preserved value
```

**Knowledge Core entry candidate**: YES
- Type: `coding_patterns`
- Confidence: High (verified in production code)
- Applicability: Any stateful processing loop
