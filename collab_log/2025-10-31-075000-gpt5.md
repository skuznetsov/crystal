# Prelude Loading Fix

## Changes
- Relaxed the prelude sanity check so that we always accept the parsed `src/prelude.cr`, even when macro expansion leaves out helpers like `Kernel.puts` or `Dir.glob`. Our LSP bootstrap now loads the real prelude successfully instead of falling back to the stub (`crystal_v2/src/compiler/lsp/server.cr`).

## Verification
- `cd crystal_v2 && CRYSTAL_CACHE_DIR=../.crystal-cache ./build_lsp_debug.sh`
- Exercised the JSON-RPC sequence (`initialize → didOpen → definition`) on `Foo#bar` inside `Foo#baz`; logs now show “Crystal prelude loaded successfully” and the definition result contains the correct span.
- `cd crystal_v2 && CRYSTAL_CACHE_DIR=../.crystal-cache crystal spec spec/lsp/lsp_rename_spec.cr`

## Impact
- Because the real prelude is in place, type inference runs during document analysis, enabling go-to-definition for member calls (`obj.method`) and other advanced LSP features without relying on the stub.
