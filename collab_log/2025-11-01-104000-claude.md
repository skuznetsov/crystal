## Solution: Add Optional Value Field

### Implementation (3 steps)

**Step 1**: Modify TypeDeclarationNode struct (ast.cr:1201-1208)
```crystal
struct TypeDeclarationNode
  getter span : Span
  getter name : Slice(UInt8)
  getter type : Slice(UInt8)
  getter value : ExprId?  # Phase 103: Optional initial value

  def initialize(@span, @name, @type, @value : ExprId? = nil)
  end
end
```

**Step 2**: Add accessor (ast.cr:2802-2810)
```crystal
# type_decl_value (Phase 103)

def self.node_type_decl_value(node : TypeDeclarationNode)
  node.value
end

def self.node_type_decl_value(node : TypedNode)
  nil
end
```

**Step 3**: Update parser to parse value when `=` found (parser.cr:257-282)
```crystal
# Phase 103: Check if followed by = (type-annotated assignment: x : Type = value)
value_expr : ExprId? = nil
if current_token.kind == Token::Kind::Eq
  advance  # consume '='
  skip_trivia

  # Parse value expression
  val = parse_expression(0)
  return PREFIX_ERROR if val.invalid?
  value_expr = val
end

# Create type declaration (with or without value)
type_decl_span = if value_expr
  left_node.span.cover(@arena[value_expr].span)
else
  left_node.span.cover(type_token.span)
end

return @arena.add_typed(
  TypeDeclarationNode.new(
    type_decl_span,
    Frontend.node_literal(left_node).not_nil!,
    type_token.slice,
    value_expr  # Phase 103: optional value
  )
)
```

### Key Design Decision

**Question**: Modify existing node or create new node?

**Decision**: Modify TypeDeclarationNode with optional value field

**Rationale**:
1. Only 1 creation site → low risk
2. Semantically correct: `x : Type = value` is single operation
3. Idiomatic Crystal: optional parameters are standard pattern
4. Zero breaking changes: default value `nil` maintains backward compatibility

### P3.3 Candidate: Complex Type Annotations

**Pattern** (1 error, line 952):
```crystal
kind : Token::Kind = case first
     ^^^^^^^^^^ namespaced type
```

**Issue**: Current parser only handles simple identifier types:
```crystal
type_token = current_token
unless type_token.kind == Token::Kind::Identifier
  emit_unexpected(type_token)  # Rejects ::
```

**Complex types not yet supported**:
- Namespaced types: `Token::Kind`, `IO::Memory`
- Generic types: `Array(Int32)`, `Hash(String, Int32)`
- Union types: `Int32 | String | Nil`
- Optional types: `Int32?` (this works as single token, but not in complex expressions)

**Complexity**: HIGH
- Need to parse type expressions, not just identifiers
- Handle `::` operator for namespaces
- Handle `()` for generics
- Handle `|` for unions
- This is effectively a mini type expression parser

**Estimated effort**: ~120 minutes (complex type parser)
