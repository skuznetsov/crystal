## Problem: Block Parameters Not Parsed

### Error Pattern
```crystal
def each_token(&block : Token ->)
  # ~~~ "unexpected Amp" at &
  # ~~~ "unexpected RParen" after ->
```

Block parameters with proc type annotations failed completely:
- `&block : Token ->` (single-arg proc)
- `&handler : String, Int32 ->` (multi-arg proc)
- `&block` (no type annotation)

### Root Cause Analysis

**Issue 1**: `&` prefix not recognized in parameter parsing
**Issue 2**: Proc type syntax not parsed (stops at first comma or closing paren)

The tricky part was multi-arg proc types like `String, Int32 ->` where the comma is part of the type signature, NOT a parameter separator.

**Phase 3**: Parse proc type with greedy token collection (parser.cr:759-809)

**Critical Insight**: NEVER break on comma before finding the `->` arrow!

The algorithm:
1. Collect all tokens after `:` until we find `->` (the arrow)
2. After finding arrow, collect optional return type
3. Only stop at delimiters (comma/rparen) AFTER we've found and processed the arrow

```crystal
if is_block
  # Phase 103: Block parameter - parse proc type
  # Key insight: NEVER break on comma before finding arrow
  type_tokens = [] of String
  found_arrow = false
  paren_depth = 0

  loop do
    break if current_token.kind == Token::Kind::EOF

    # Track parentheses for complex proc types
    if operator_token?(current_token, Token::Kind::LParen)
      paren_depth += 1
    elsif operator_token?(current_token, Token::Kind::RParen)
      break if paren_depth == 0  # Closes parameter list
      paren_depth -= 1
    end

    # Check for -> (proc type arrow)
    if current_token.kind == Token::Kind::ThinArrow
      type_tokens << token_text(current_token)
      advance
      found_arrow = true
      next  # Continue to collect optional return type
    end

    # AFTER finding arrow, stop at delimiters
    if found_arrow && paren_depth == 0
      break if current_token.kind == Token::Kind::Comma
      break if operator_token?(current_token, Token::Kind::RParen)
    end

    # BEFORE finding arrow, collect everything (including commas)
    type_tokens << token_text(current_token)
    advance

    if current_token.kind == Token::Kind::Whitespace
      advance
    end
  end

  type_annotation = type_tokens.join(" ") unless type_tokens.empty?
end
```

### Key Design Decision

**First attempt**: Stop at comma if no arrow found → FAILED
**Second attempt**: Keep collecting until arrow found → SUCCESS

The issue was distinguishing:
- `&block : Token` (no proc type, just type annotation) - should stop at comma
- `&block : String, Int32 ->` (proc type) - comma is part of type

Solution: Be greedy. Always collect tokens until seeing `->`, then collect return type, then stop.

## Knowledge Core Entry

**Pattern**: Greedy Type Collection for Proc Parameters

**Problem**: Multi-arg proc types have commas that look like parameter separators
```crystal
&handler : String, Int32 ->  # comma is part of proc type!
```

**Solution**: Collect tokens greedily until finding `->`, then collect return type
- BEFORE arrow: never break on comma (it's part of type)
- AFTER arrow: break on comma/rparen (it's a delimiter)

**Applicability**:
- Any context where type annotations can contain commas (proc types, tuple types)
- When delimiter tokens (comma, paren) have dual meanings based on context
- When type system syntax is complex and context-dependent

**Anti-patterns**:
- ❌ Break on first comma (assumes simple types)
- ❌ Look-ahead for arrow (complex, error-prone)
- ✅ Greedy collection until marker token found
