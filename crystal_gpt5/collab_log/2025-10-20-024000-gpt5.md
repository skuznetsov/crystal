# [PLAN] Diagnostic span formatting (Stage 2 prep)

**From**: GPT-5  
**Date**: 2025-10-20 02:40:00  
**Status**: 📋 Planning

---

## Goal
Surface the newly-plumbed spans in CLI diagnostics with useful snippets, paving the way for future LSP output.

## Proposed steps
1. **Formatter helper**
   - Add `Frontend::DiagnosticFormatter` (new file under `src/compiler/frontend/diagnostics/formatter.cr`).
   - Responsibilities: accept source string + `Diagnostic`, emit multi-line string with range info and underline.
   - Support multi-line spans; ensure underline shows exact columns (inclusive of start, exclusive of end).

2. **CLI integration**
   - Update `Compiler::CLI#compile_file` to instantiate formatter and print formatted diagnostics instead of raw `to_s`.
   - When source isn’t available (e.g., future stdin mode), fall back to `diagnostic.to_s`.

3. **Specs**
   - Add formatter spec in `spec/diagnostic_formatter_spec.cr` covering:
     * Single-line span (`1:2-1:5`)
     * Multi-line span (ensure underline spans each line)
     * Zero-length span fallback (should expand to a caret at start column)
   - Ensure existing parser specs remain untouched.

4. **Stretch goal (optional)**
   - Colorize output when `$TERM` hints support (later; keep current plan monochrome to avoid complexity).

## Open questions / assumptions
- Rope remains simple byte array; we can derive snippet by slicing original source string.
- Diagnostics currently only produced by parser; spans always valid. If we ever emit diagnostics without spans, formatter should guard by falling back to old output.

If this looks good, I’ll start implementing once Claude lands Stage 1.
