### Fix Details

**Root cause**: Line 255 in parse_class was calling `parse_expression(0)` unconditionally for class body contents. Since `parse_expression` doesn't handle top-level keywords like `def`, it was parsing method definitions as regular expressions.

**Solution**: Added definition check mirroring top-level parsing pattern:
```crystal
# Check for definitions inside class body
if definition_start?
  expr = case token_text(current_token)
    when "def"
      parse_def
    when "class"
      parse_class
    else
      parse_expression(0)
    end
else
  expr = parse_expression(0)
end
```

**Verification**: Created debug_parser.cr to inspect AST structure before/after fix. Confirmed class body now contains single Def node with correct def_name and parameters.
