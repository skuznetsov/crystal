## Problem: Multi-line When Clauses Failing

### Error Pattern
```crystal
case @last_token_kind
when Token::Kind::Identifier, Token::Kind::Number,
     Token::Kind::String, Token::Kind::Char
  # ^^^ "unexpected Newline" after comma
  false
end
```

Multi-line when clauses with comma-separated conditions failed with "unexpected Newline" after each comma.

### Root Cause Analysis

**Issue**: In `parse_case`, when parsing comma-separated conditions (lines 1121-1124), code used `skip_trivia` after comma:

```crystal
loop do
  cond = parse_expression(0)
  conditions << cond

  skip_trivia  # <-- Only skips whitespace/comments, NOT newlines!
  break unless current_token.kind == Token::Kind::Comma
  advance  # consume comma
  skip_trivia  # <-- Problem: newlines NOT allowed after comma
end
```

**Pattern Discovery**: Checked how multi-line argument lists work in `parse_parenthesized_call`:
- Uses `skip_whitespace_and_optional_newlines` after commas (line 5001)
- Works because `@paren_depth > 0` makes `inside_delimiters?` return true

**Key Insight**: when clauses don't have delimiter depth tracking, but comma-separated lists should still allow newlines after commas. Solution: Use `consume_newlines` (which skips ALL newlines) instead of `skip_trivia`.

This is consistent with how we handle control structure keywords - newlines are structurally acceptable after commas in when clauses.

## Solution: consume_newlines After Comma

### Implementation

**File**: `src/compiler/frontend/parser.cr`
**Location**: Lines 1113-1125 (parse_case method, when condition parsing)

**Change**:
```crystal
# BEFORE:
skip_trivia
break unless current_token.kind == Token::Kind::Comma
advance  # consume comma
skip_trivia  # <-- Problem

# AFTER:
skip_trivia
break unless current_token.kind == Token::Kind::Comma
advance  # consume comma
consume_newlines  # Phase 103: allow newlines after comma
```

**Rationale**: Comma is a separator in when clause conditions, similar to structural keywords. Newlines after separators are syntactically valid.

## Knowledge Core Entry

**Pattern**: Multi-line Comma-Separated Lists in Control Structures

**Problem**: When clauses with comma-separated conditions fail on newlines after commas
```crystal
when A, B,
     C, D  # Newline rejected
```

**Solution**: Use `consume_newlines` instead of `skip_trivia` after commas in when conditions

**Context Comparison**:
- **Delimiter-scoped** (parentheses, brackets): Use `skip_whitespace_and_optional_newlines` (checks delimiter depth)
- **Control structures** (when, if, while): Use `consume_newlines` (structural newlines)

**Applicability**:
- Any control structure with comma-separated lists
- When lists that are NOT inside delimiters
- Comma is a separator, not an operator

**Anti-patterns**:
- ❌ Use `skip_trivia` after separators (rejects newlines)
- ❌ Require delimiter depth for control structures (over-engineering)
- ✅ Use `consume_newlines` for structural comma lists

**Confidence**: 0.95 (tested on real compiler code)
